# Independent scope implementation review — 2026-09-07

Review owner changed tests only. Production findings sent to implementation and orchestration owners; these are findings against the initial implementation, not final unresolved claims. Line references identify that reviewed snapshot and may shift as fixes land.

1. **Scope array exports cannot compose with for_each** (`src/definition.ts:270`). Validator checks only dependency.outputs while scopes hold export bindings separately and initialize outputs empty. A child `items: string[]` exported through a scope is rejected as a for_each source. Added regression in `tests/e2e/scope-composition.test.ts`.
2. **Scope commit publication is not atomic** (`src/activities.ts:71`). Writing directly to accepted output.json with `wx` can leave a partial final path after crash; retry JSON parsing then fails permanently. Existing provider receipt writer uses temporary-file plus atomic publication. New scope evidence needs equivalent publication and explicit corruption rejection.
3. **Scope acceptance omits schema and child evidence validation** (`src/activities.ts:61-76`). Input data is type-cast, output self-hashed and children stored as IDs. No exported schema validation or binding to verified committed child content occurs. Owner is adding inferred export schemas and child hashes. Verify all accepted scope artifacts, not just provider receipts.
4. **Runtime global expansion accounting is incomplete** (`src/workflows.ts:517,536,624`). Counter covers child registration/nested map lengths but omits agent loop iterations and top-level maps. Example scoped agent loop max20 plus map990 can execute over1000 leaf iterations despite counter992. Preserve ordinary legacy behavior while enforcing the new global budget consistently for scope-enabled workflows. Added top-level map rejection test requiring zero provider receipts; do not execute 1001 items while the guard is missing.
5. **Legacy predicate replay risk** (`src/loop.ts:21-24`). New missing/non-numeric operand errors change existing flat loop decisions that formerly evaluated false (or true for not_equals). A prior history recording continued iterations can diverge under the new bundle. Preserve old flat predicate semantics through an explicit version/feature contract or provide representative replay evidence for this behavior, not just ordinary successful histories.

Follow-up verification should rerun the independent boundary/composition suites against a stable worker bundle, confirm atomic scope commit/corruption tests, inspect scope evidence schemas/hashes, and replay both ordinary and predicate-edge histories. Human restart/replay coverage is being added by the implementation owner independently.
